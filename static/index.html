填三项就能跑通第一条隧道；下面的数字是当前状态，细节到各标签页微调。

开始使用

验证 Token → 选域名 → 备隧道 → 写规则下发路由 → 启动连接器，一次点完。

需要「区域读取 + 编辑、Cloudflare Tunnel 编辑」权限。
小写字母 / 数字 / 连字符；@ 为根域名。
只填端口按本机 HTTP 处理；其它协议写完整地址。
账号下有多个域名时才需要选。
同名规则会被覆盖成新的服务地址，可放心再点一次。
    现在可以访问 –
    隧道总数–Cloudflare 账号内
    Ingress 规则–子域名 → 本地服务
    连接器–cloudflared 进程
    默认 Zone–Ingress 取此域名

    一条规则怎么才算通

    三件事同时成立，浏览器才可能访问到域名。

    1. 1 隧道路由已下发Cloudflare 侧 Ingress 里要有这个 hostname，并且末尾保留一条不带域名的兜底规则。保存规则时面板会自动下发；失败会出现「路由未下发」标签，到「隧道」页点「重新下发路由」。
    2. 2 DNS 指向隧道子域名要有一条已代理的 CNAME 指向 <tunnel-id>.cfargotunnel.com。缺少时规则上会出现「DNS 已缺失」标签。
    3. 3 连接器正在运行本机 cloudflared 用该隧道的令牌连上云端，流量才会送进 NAS。令牌可在隧道页「令牌」取得。

    02 / Tunnels

    隧道

    创建 / 删除 Cloudflare 命名隧道，一键连接或断开；Ingress 规则在下方按隧道维护。

    新建 创建命名隧道
    小写字母、数字与连字符，1-63 位；名称在账号内唯一。

    隧道列表

    「已连接」表示云端活跃，且本机 cloudflared 正在跑这条隧道。

    Ingress 规则

    子域名 → 本地服务；保存时写入所选隧道的路由并创建已代理 CNAME。

    新建 添加 Ingress 规则
    小写字母 / 数字 / 连字符，1-63 位；@ 为根域名，* 为泛域名。
    面板会把该隧道的所有规则整份下发，末尾自动补兜底规则。
    03 / Zones & DNS

    域名与 DNS

    选 Zone 与查看 Cloudflare 记录；Ingress 规则在「隧道」页里按隧道维护。

    Cloudflare 域名（Zone）

    从账号拉取域名，选中的一条作为添加规则时的默认 Zone。

    Cloudflare DNS 记录

    当前 Zone 下的全部 DNS 记录，标注本面板维护的条目。

    还没有加载记录
    点击右上角「刷新记录」拉取当前 Zone 的 DNS 记录

    05 / Settings

    设置

    Cloudflare 凭据、面板密码与配置备份，全部保存在本机数据目录。

    Cloudflare 凭据

    先「测试配置」确认权限齐不齐，再保存。

    创建 API Token 需要哪些权限？
    • 账户 → Cloudflare Tunnel：编辑 + 读取
    • 区域 → DNS：编辑 + 读取
    • 区域 → 区域：读取

    在 Cloudflare API Tokens 创建「自定义令牌」时按以上勾选即可。

    测试配置后自动获取；多账号需手动填写

    面板密码

    修改后所有会话立即失效，需要用新密码重新登录。

    至少 8 位。若 API Token 曾外泄，请同时到 Cloudflare 后台轮换 Token。

    配置备份

    导出为 JSON（含 API Token，请妥善保管）；换机、重装或误操作后用它还原。

    确认 将覆盖当前 Cloudflare 凭据与连接器设置
